1Qué es

IBKR Dashboard es un dashboard personal de cartera para una sola cuenta de Interactive Brokers. Un único usuario, sin autenticación, que corre en local tras un stack de docker-compose (OrbStack en Mac).

  • Backend: FastAPI + SQLAlchemy + APScheduler. Ingiere XML del Flex Web Service de IBKR, parsea las secciones a una base SQLite (portable a Postgres) y expone 52 endpoints JSON.
  • Frontend: React + Vite + recharts (nginx estático con proxy /api).

El dashboard se organiza en 10 pestañas, cada una consumiendo la API directamente:

Resumen Cartera Fiscal Operaciones Opciones Dividendos Rentabilidad Comisiones Margen Integraciones

Filosofía de datos

El Flex Web Service es la vía de ingesta canónica. Los exports XML/CSV en Extractos/ son el Plan B cuando el token se rompe. No hay métricas inventadas: toda cifra traza a un campo de IBKR (fifoPnlRealized, netCash, fxRateToBase) o a un cálculo transparente sobre ellos. No-objetivos: multi-cuenta, multi-broker, móvil, tiempo real.

4Setup de Flex Queries en IBKR

El backend necesita dos Flex Queries guardadas en tu Client Portal, y sus IDs en el .env. Detalle completo en docs/setup/flex-queries.md.

4.0 Generar el token del Flex Web Service

  1. Client Portal → Performance & Reports → Flex Queries.
  2. Baja al final: Flex Web Service → Generate Token.
  3. Guarda el número de 20-30 dígitos en IB_FLEX_TOKEN. El token caduca al final de su Activation Period en el portal (a menudo ~1 año); pon esa fecha en IB_FLEX_TOKEN_EXPIRY; renuévalo antes de que caduque o el pipeline devuelve HTTP 604.

4.1 Activity Flex Query (dashboard_full_daily)

Es el snapshot diario que alimenta casi todas las pestañas. Crear: Flex Queries → Activity Flex Query → Create.

Cabecera

CampoValor
Query Namedashboard_full_daily
PeriodLast 30 Calendar Days (recomendado; idempotente, recupera huecos de menos de 30 días. Year to Date lo entregó IBKR truncado y congeló los datos 2026-08-17→09-12)
Date Format / Time FormatyyyyMMdd / HHmmss
Date/Time Separator;
Include Canceled Trades?No
Include Currency Rates?Yes
FormatXML

Secciones a marcar

Marca todas estas (y dentro de cada una, todas las columnas - el parser tolera columnas extra pero falla en silencio si faltan):

  • Account Information
  • Net Asset Value (NAV) in Base · Change in NAV in Base
  • Cash Report · Open Positions (Summary) · Trades (Execution) · Cash Transactions
  • Open Dividend Accruals · Interest Accruals · Transaction Taxes
  • Conversion Rates · Securities Info · Corporate Actions
  • FIFO Performance Summary in Base · MTM Performance Summary in Base
  • Option Exercises, Assignments, Expirations · Transfers (defensivos)

Al guardar verás un Query ID de 8 dígitos → ponlo en IB_FLEX_QUERY_ID.

4.2 Trade Confirmation Flex Query (dashboard_tc_daily)

Fills por ejecución con timestamps de colocación de orden (orderTime) y desglose completo de comisión. Crear: Flex Queries → Trade Confirmation Flex Query (¡no Activity!) → Create.

CampoValor
Query Namedashboard_tc_daily
PeriodToday (única opción para TC; el CLI hace backfill con --from/--to)
Output FormatXML
Date / Time Formatyyyy-MM-dd / HH:mm:ss, separador ;
Display CurrencyBase Currency Summary

Una sola sección: Trade Confirms → activa todas las columnas. Guarda y pon el ID en IB_FLEX_QUERY_ID_TC. Luego recrea el backend para que tome la variable:

docker compose up -d --force-recreate backend
docker exec ibkr-backend env | grep IB_FLEX_QUERY_ID_TC

Renovación del token

El token caduca al final de su Activation Period (a menudo ~1 año) y el pull diario empieza a devolver HTTP 604. Regenéralo en Flex Web Service → Generate Token, sustituye IB_FLEX_TOKEN y IB_FLEX_TOKEN_EXPIRY en .env y haz docker compose up -d --force-recreate backend. Comprueba curl -sf http://localhost:5173/api/health (nginx re-resuelve el backend solo, sin reiniciar el frontend). Las queries guardadas no caducan, solo el token.

Invoca docker compose siempre desde la raíz del repo (los bind mounts usan rutas relativas: ./Extractos, ./price_alerts.yaml).

6Primera ingesta de datos

El esquema se crea solo (los comandos llaman a init-db internamente). Para el primer pull:

docker exec ibkr-backend python -m ibkr_backend.cli pull

Sin --period: las queries guardadas tienen periodo fijo y rechazan el override con HTTP 604.

El CLI imprime un recuento de filas por sección. Espera valores no-cero en nav_daily, change_in_nav, trades, cash_transactions, fifo_performance, mtm_performance.

Bootstrap histórico

# Backfill de N años en ventanas de 365 días
docker exec ibkr-backend python -m ibkr_backend.cli bootstrap --years 4

# Solo si la BD está vacía (idempotente - útil en primer arranque)
docker exec ibkr-backend python -m ibkr_backend.cli bootstrap-if-empty --years 4

Trade Confirmations

# Hoy (lo que hace el cron)
docker exec ibkr-backend python -m ibkr_backend.cli pull-tc

# Backfill de los últimos 30 días (techo TC: 45 días)
docker exec ibkr-backend python -m ibkr_backend.cli pull-tc \
    --from $(date -v-30d +%Y%m%d) --to $(date +%Y%m%d)

Plan B - cuando el token falla

Si el Flex token está roto, carga cualquier export guardado en Extractos/ (montado en /app/Extractos):

docker exec ibkr-backend python -m ibkr_backend.cli load-xml /app/Extractos/<file>.xml

Verificar los runs

docker exec ibkr-backend python -m ibkr_backend.cli runs
# o vía API:
curl http://localhost:8001/pipeline/runs

La lista completa de comandos CLI está en la § Referencia: comandos CLI.

7El scheduler (automático)

El backend monta un APScheduler con estos jobs principales. APScheduler dispara en la TZ del contenedor - compose fija TZ=Europe/Zurich, así que los crons son hora de Zúrich. Sin esa variable (imagen standalone) cae a UTC.

JobCron (default)Qué hace
Pull diario30 6 * * * → 06:30 ZúrichEjecuta el pipeline completo de Activity Flex (run_full_pipeline) y, tras el pull, dispara el digest de Telegram si está configurado.
Reintento del pull diario30 8,12 * * * → 08:30 y 12:30 ZúrichSolo si el slot de las 06:30 no tiene ningún pull programado con éxito (mismo predicado que el catch-up de arranque); nunca repite un pull bueno.
Pull Trade Confirms15 * * * * → cada hora al :15, todos los díasRe-tira las Trade Confirmations (run_tc_pipeline). Idempotente, las re-ejecuciones son gratis.
Watchdog de staleness0 */6 * * * → cada 6hAlerta por Telegram (deduplicada) si no hay pull con éxito en 30 h (PIPELINE_STALE_AFTER_HOURS) o si positions_eod no avanza en 3 días hábiles (data_freshness).
Alertas de precio*/15 * * * mon-friEvalúa reglas live de price_alerts.yaml cuando IB Gateway está activo. No se programa mientras ENABLE_LIVE_OVERLAY=false. Los crons usan nombres de día: el día de la semana de APScheduler es 0=lunes (no el 0=domingo del cron estándar).
Alerta de margen live*/3 * * * *Evalúa valores oficiales de cuenta IBKR y alerta solo cuando empeora la banda o se recupera.
Revisión de divisa0 8 * * mon → lunes 08:00Si existe deuda, compara tipos IBKR Pro y un replay ECB de 365 días frente al CHF.
Retención de flex_runs15 4 * * * → 04:15 ZúrichBorra las ejecuciones TC con éxito y 0 filas insertadas de más de 90 días (FLEX_RUNS_RETENTION_DAYS).
Backup nocturno de la BD45 3 * * * → 03:45 ZúrichCopia online de SQLite a /backups (host: ~/.ibkr-backups), conserva 14. Solo si BACKUP_DIR está definido (compose lo define).
Sidecar watchdog (contenedor aparte)cada 300 sLee /pipeline/status y reinicia el backend si el scheduler se cuelga (heartbeat > 30 min, ningún pull despachado en 3 h, o API sin respuesta ×3). Monta docker.sock. Script: deploy/watchdog/watchdog.sh.

Monitorización del estado

El estado de staleness se expone en GET /pipeline/status bajo staleness.is_stale - un monitor externo puede leerlo y actuar.

8Notificaciones por Telegram nuevo

Tras cada pull diario con éxito, el backend envía un digest del día anterior a tu chat de Telegram. Se activa solo si .env tiene TELEGRAM_BOT_TOKEN y TELEGRAM_CHAT_ID (off por defecto).

Qué reporta

  • Dividendos cobrados - bruto / retención / neto, nº de acciones y dividendo por acción.
  • Operaciones - trades de acciones y opciones, incluyendo ejercicio/asignación de opciones y depósitos/retiradas.
  • Comisiones - acumulado del mes en curso.
  • Margen live - cushion, exceso de liquidez y look-ahead, con bandas 30/20/10 % y anti-spam.
  • Divisa de financiación - revisión semanal separando el menor tipo actual del mejor replay histórico contra CHF.

Obtener el chat_id

  1. Crea el bot con @BotFather y copia el token.
  2. Escríbele un mensaje al bot desde tu cuenta.
  3. Abre en el navegador https://api.telegram.org/bot<token>/getUpdates y copia el chat.id que aparece.
  4. Pon ambos valores en .env y recrea el backend.

Comandos de prueba

# Mensaje de prueba de una línea (verifica token + chat_id)
docker exec ibkr-backend python -m ibkr_backend.cli notify-test

# Previsualizar el digest de un día SIN enviar ni mover el watermark
docker exec ibkr-backend python -m ibkr_backend.cli notify-now --test --date 2026-06-11

# Enviar el digest de un día concreto (fuerza el envío)
docker exec ibkr-backend python -m ibkr_backend.cli notify-now --date 2026-06-11

# Sin --date: reporta "ayer" y avanza el watermark
docker exec ibkr-backend python -m ibkr_backend.cli notify-now
# Previsualizar margen live o el fallback EOD, sin enviar
docker exec ibkr-backend python -m ibkr_backend.cli margin-alert --source live --test
docker exec ibkr-backend python -m ibkr_backend.cli margin-alert --source eod --test

# Comparación de divisa sin enviar
docker exec ibkr-backend python -m ibkr_backend.cli margin-financing

Anti-duplicados

Hay un watermark (NotificationState) que impide reenviar el mismo día. notify-now --date fuerza el envío sin tocar el watermark; el job automático sí lo avanza.

Migración desde una hoja legacy

Si vienes de una automatización previa, para su envío automático para no duplicar las notificaciones.

9Mantenimiento de datos: dedup CSV+Flex nuevo

El problema: importar por CSV (Extractos/, Plan B) y por Flex crea filas duplicadas con PK distinta - la misma operación entra dos veces, una con clave csv_* y otra con la clave de Flex.

El comando borra solo las filas csv_* que tienen gemelo de Flex (misma clave económica); conserva los huérfanos CSV y los fills genuinos repetidos.

# Dry-run: solo informa, no borra nada
docker exec ibkr-backend python -m ibkr_backend.cli dedup-csv-imports

# Aplicar: borra los duplicados (¡haz backup antes!)
docker exec ibkr-backend python -m ibkr_backend.cli dedup-csv-imports --apply

Antes de --apply

Haz un backup de la BD (ver §10). El dry-run muestra, por tabla: total, removable csv, orphan csv kept y genuine groups - revísalo antes de borrar.

10Backups

La BD vive en el volumen Docker ibkr_dashboard_db_data; dentro del contenedor está en /app/data/ibkr_backend.db. Los backups manuales viven en ~/.ibkr-backups/.

docker cp ibkr-backend:/app/data/ibkr_backend.db \
    ~/.ibkr-backups/ibkr_backend.$(date +%Y%m%d).db

Hazlo siempre antes de operaciones destructivas (dedup-csv-imports --apply, reconcile-cashflows). El volumen sobrevive a mover el directorio del repo, pero un backup en disco es la red de seguridad real.

12Troubleshooting / gotchas

SíntomaCausa / regla
Flex HTTP 604Token caducado (fin de su Activation Period, ver token_expiry en /pipeline/status), query ID desactivada, formato de salida ≠ XML, o un --period sobre una query de periodo fijo. Diagnostica en el IBKR Portal; mientras tanto usa load-xml sobre cualquier export de Extractos/.
netCashYa descuenta ibCommission - trata la comisión solo como desglose, nunca la re-restes.
Multiplicador de derivadosYa está aplicado en OpenPositions.positionValue y Trades.proceeds - no multipliques a mano.
CI rojo de repenteAlguien re-añadió --basetemp a pytest. El runner de GitHub no puede crear el .tmp/ padre; usa el temp por defecto del OS.
Withholding tax UNKNOWNEl país se parsea del sufijo ' - XX TAX' de la descripción, con fallback a Instrument.issuer_country. UNKNOWN es normal en algunas descripciones no-US.
IdempotenciaLas claves son IDs suministrados por IBKR. Nunca cambies una fórmula de id sintético sin re-bootstrapear (duplicados garantizados).
